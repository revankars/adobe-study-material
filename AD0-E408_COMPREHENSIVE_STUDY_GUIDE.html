Domain Focus: Understanding business objectives, identifying optimization opportunities, and planning effective testing strategies. You must translate business goals into Target activities.

1.1 Business KPIs and Performance Analysis

Key Performance Indicators are measurable values showing how effectively business goals are being achieved.

Connecting Business Goals to Target Implementation

E-Commerce Goal Chain:
  • Business Goal: Increase average order value
  • KPI: AOV (Average Order Value)
  • Target Success Metric: Revenue (RPV)
  • Activity Type: Personalization

1.2 Optimization and Experimentation Strategies

Activity Type Selection Guide

A/B Testing
  • When: Comparing 2-3 designs
  • Purpose: Find statistical winner
  • Requires: Sample size + 95% confidence
Experience Targeting (XT)
  • When: Different audiences need different messaging
  • Purpose: Audience-specific mapping
  • No: Statistical comparison
Multivariate Testing (MVT)
  • When: Testing 3+ elements simultaneously
  • Requires: Very high traffic (500K+)
  • Duration: 4-8 weeks
Auto-Target
  • When: ML personalization per visitor
  • Personalizes: Whole page experience
  • Variations: 2-5 complete designs
Automated Personalization (AP)
  • When: ML offer combinations
  • Multiple: Offers in multiple locations
  • Complexity: Very high traffic (1M+)
Recommendations
  • When: Product/content recommendations
  • Algorithms: Items viewed, trending, popular
  • Ongoing: Continuous optimization

1.3 Hypothesis Construction

Hypothesis Formula: "If we [ACTION], then [OUTCOME] because [REASONING]"
⚠️ Critical Exam Concept: Hypotheses must be testable, specific, reasonable, measurable, and realistic. Base them on data or user research, not intuition.

1.7 A/B Testing Best Practices

The Golden Rules

  1. Wait for Calculated Sample Size - Most critical rule. Prevents false positives.
  2. Maintain 95%+ Confidence - Only 5% false positive risk
  3. Avoid Peeking - Multiple checks inflate false positive risk
  4. Account for Novelty Effect - New designs perform better initially
  5. Identify Confounds - External events can skew results
🔴 Common Pitfalls:
  • Peeking at results (increases false positives from 5% to 20%+)
  • Stopping early when lift looks good (before sample size)
  • Not accounting for novelty effect (new designs initially outperform)
  • Testing without calculating sample size first
  • Confusing percentage points with relative lift

Domain 2: Configuration, Executing & Managing (50%)

⚠️ IMPORTANT: Domain 2 is 50% of the exam (~26 questions). Mastering this domain is critical.

2.1 Visual Experience Composer (VEC)

VEC: Point-and-click visual interface for creating experiences without coding

What VEC Can Edit

  • ✓ Text content (headlines, copy, button labels)
  • ✓ Images (replacements, modifications)
  • ✓ Styling (colors, fonts, spacing)
  • ✓ Structure (hide/show, rearrange, remove, add)
  • ✓ Links & attributes (URLs, alt text, titles)

What VEC Cannot Edit

  • ✗ iFrames (browser security)
  • ✗ Heavily JavaScript-rendered content
  • ✗ Third-party widgets
  • ✗ Server-side dynamic content
CSS Selector Stability: This is a frequent exam topic. Avoid deeply nested selectors. Use Expand Section to select parent elements (especially those with unique IDs).

Key VEC Features

Feature Purpose When to Use
Expand Section Select parent element for stability When selectors break after page updates
!important CSS Override page CSS conflicts When Target CSS doesn't appear
URL Targeting Apply activity to multiple pages Multi-page campaigns
Edit HTML Direct code editing Complex changes, JavaScript issues

2.2 Form-Based Experience Composer

Form-Based Composer: Non-visual interface for creating experiences without page rendering

When to Use Form-Based

  • Non-website channels (email, apps, APIs, kiosks)
  • VEC fails to load pages
  • JavaScript-heavy pages with timing issues
  • Protected pages (authentication required)
⚠️ Critical: Redirect offers can ONLY be created in Form-Based Composer, NOT in VEC.

Content Types in Form-Based

  • HTML Offer: Custom HTML code
  • JSON Offer: Structured data for SPAs/APIs
  • Image Offer: Image URL replacement
  • Redirect Offer: Send to different URL (Form-Based only)

2.3 Activity Configuration

Universal Activity Setup Flow

  1. Choose Activity Type
  2. Configure Audience Targeting
  3. Set Goals & Settings (success metrics, duration, priority)
  4. Create Experiences/Offers
  5. QA & Launch

Success Metrics Configuration

Setting Default Meaning
Increment Count & Keep User Yes (default) Visitor stays in activity, can convert multiple times
Release & Allow Reentry Optional Visitor exits, can re-enter in future sessions
Release & Bar Reentry Optional Visitor permanently removed (one-time offers)

Activity Priority Settings

  • Always check: Activity Collisions tab to see conflicts

2.4 Activity Types in Detail

Automated Personalization (AP) - Unique Characteristics

  • What it tests: Offer combinations (not page designs)
  • Locations: Multiple areas with offers
  • Combinations: Multiply offers per location (Location A offers × Location B offers × ...)
  • Max Experiences: Up to 30,000 (much higher than other activity types)
  • Traffic Required: Very high (1M+ monthly)
AP Unique Reports (4 Types):
  1. Activity Level Report: Control vs. Targeted
  2. Offer Level Report: Each offer's Random vs. Smart performance
  3. Automated Segments Report: Auto-discovered visitor groups
  4. Important Attributes Report: Attribute usage frequency

2.5 QA Procedures and Preview Modes

🔴 Important: QA conversions are NOT recorded in reporting. Use QA to test without affecting data.

Preview Settings

Setting Isolated (ON) Realistic (OFF)
Show default for other activities See ONLY your activity See with other live activities (collisions visible)
Match audience rules Bypass rules (debug mode) Respect rules (production-like)
Use case Testing your content in isolation Validating real-world behavior

QA Workflow

  1. Configure preview settings
  2. Access activity and verify content displays
  3. Validate all elements (text, images, styling)
  4. Test conversion actions
  5. Check on multiple devices/browsers
  6. Exit QA mode

Domain 3: Analyzing & Reporting (16%)

3.1 Understanding Statistical Concepts

Conversion Rate

Formula: (Conversions / Visitors) × 100
Example: 50 conversions / 1,000 visitors = 5%

Lift

Formula: (Variation% - Control%) / Control% × 100
Example: (6% - 5%) / 5% × 100 = 20% lift
⚠️ Common Confusion: 20% lift in relative terms ≠ 20 percentage points
20% relative lift = 1 percentage point absolute difference (5% → 6%)

Confidence and Significance

Confidence Level False Positive Risk Action
95%+ Confidence 5% (acceptable) DECLARE WINNER
80-94% Confidence 6-20% (high risk) Continue testing
<80% Confidence >20% (very high) Much more data needed
Sample Size Importance: You MUST reach calculated sample size before declaring winner, even if confidence seems high at 85-90%.

3.2 Automated Personalization Reporting

Report 1: Activity Level Report

  • Shows: Control (random) vs. Targeted (AI)
  • Answers: "Is personalization working?"

Report 2: Offer Level Report

  • Shows: Each offer's Random vs. Smart performance
  • Key: Compare same offer (Random vs. Smart), NOT different offers

Report 3: Automated Segments Report

  • Shows: Auto-discovered visitor groups
  • Reveals: Which segments prefer which offers

Report 4: Important Attributes Report

  • Shows: Which attributes ML used most
  • CRITICAL MISUNDERSTANDING: This is FREQUENCY of use, NOT causation
🔴 Important Attributes Mistake:
❌ "Device Type causes 28% of conversions"
✅ "Algorithm used Device Type in 28% of decisions"

3.3 Multivariate Testing Reporting

Experience Performance Report

  • Shows each element combination's performance
  • Comparison of all combinations side-by-side

Element Contribution Analysis

  • Breaks down impact of individual elements
  • Shows which variables matter most

Bonferroni Correction

  • What it does: Adjusts significance threshold for multiple comparisons
  • Why: Testing many elements inflates false positive risk
  • Solution: Stricter threshold per comparison

3.4 Interpreting Confidence Intervals

Example:
Variation: 6.2% ± 0.4%
95% Confidence Interval: 5.8% - 6.6%
Means: 95% confident true rate is between 5.8% - 6.6%

Overlapping vs. Non-Overlapping Intervals

  • Intervals OVERLAP: No significant difference (continue testing)
  • Intervals DON'T OVERLAP: Significant difference (safe to declare winner)

Domain 3 Summary

  • Understand conversion rate, lift, confidence calculations
  • Know 95%+ confidence requirement for declaring winner
  • Know sample size is CRITICAL (non-negotiable)
  • Understand false positive risks and causes
  • Know AP's 4 unique report types
  • Remember: Important Attributes ≠ causation
  • Understand novelty effect in test interpretation
  • Can interpret confidence intervals

Domain 4: Troubleshooting (8%)

4.1 Activity Delivery Troubleshooting

Systematic Troubleshooting Checklist

  1. Verify Activity Status: Active? Past start date? Before end date?
  2. Verify Audience: Do you match audience rules?
  3. Verify URL Targeting: Current page matches URL rules?
  4. Clear Browser Cache: Try incognito/private mode
  5. Check Target Library: at.js or alloy.js loaded in console?
  6. Check Collisions: Higher priority activities hiding yours?
  7. Verify CSS Selectors: Page design changed? Selectors broken?

4.2 Audience Qualification Issues

Common Audience Problems

  • No visitors qualify: Check AND/OR logic, attribute population
  • Wrong audience assigned: Verify audience definition
  • Profile attributes missing: Confirm parameter passing
Debug Checklist:
  • Check browser console for mbox calls
  • Verify parameters are being sent
  • Check parameter names match exactly
  • Validate audience works in isolation

4.3 Debugging Tools

Tool Purpose Detail Level When to Use
mboxDebug (?mboxDebug) Basic request/response inspection Low Quick checks
mboxTrace (?mboxTrace=true) Detailed tracing of decisions High Deep debugging
Debugger Extension Graphical debugging interface Medium Visual inspection
Browser Console (F12) JavaScript-level debugging High Error investigation

4.4 Preset Issues

Preset: Saved reporting configuration that depends on referenced objects (audiences, metrics)

When Presets Become Invalid

  • Referenced audience deleted
  • Referenced metric removed
  • Referenced objects changed/renamed

Fixing Invalid Presets

  1. Identify missing/changed object
  2. Recreate with original definition (or update references)
  3. Preset automatically becomes valid

Domain 4 Summary

  • Follow systematic troubleshooting approach
  • Know when to check each factor (status, audience, URL, cache, collisions)
  • Use appropriate debugging tool for situation
  • Understand preset dependencies
  • Know how to fix invalid presets
