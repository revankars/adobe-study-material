Domain 1: Planning & Strategy (26%)

Domain Focus: Understanding business objectives, identifying optimization opportunities, and planning effective testing strategies. You must translate business goals into Target activities.
1.1 Business KPIs and Performance Analysis

Key Performance Indicators are measurable values showing how effectively business goals are being achieved.

Connecting Business Goals to Target Implementation
E-Commerce Goal Chain:
  • Business Goal: Increase average order value
  • KPI: AOV (Average Order Value)
  • Target Success Metric: Revenue (RPV)
  • Activity Type: Personalization
1.2 Optimization and Experimentation Strategies
Activity Type Selection Guide
A/B Testing
  • When: Comparing 2-3 designs
  • Purpose: Find statistical winner
  • Requires: Sample size + 95% confidence
Experience Targeting (XT)
  • When: Different audiences need different messaging
  • Purpose: Audience-specific mapping
  • No: Statistical comparison
Multivariate Testing (MVT)
  • When: Testing 3+ elements simultaneously
  • Requires: Very high traffic (500K+)
  • Duration: 4-8 weeks
Auto-Target
  • When: ML personalization per visitor
  • Personalizes: Whole page experience
  • Variations: 2-5 complete designs
Automated Personalization (AP)
  • When: ML offer combinations
  • Multiple: Offers in multiple locations
  • Complexity: Very high traffic (1M+)
Recommendations
  • When: Product/content recommendations
  • Algorithms: Items viewed, trending, popular
  • Ongoing: Continuous optimization
1.3 Hypothesis Construction
Hypothesis Formula: "If we [ACTION], then [OUTCOME] because [REASONING]"
⚠️ Critical Exam Concept: Hypotheses must be testable, specific, reasonable, measurable, and realistic. Base them on data or user research, not intuition.

1.7 A/B Testing Best Practices
The Golden Rules
  1. Wait for Calculated Sample Size - Most critical rule. Prevents false positives.
  2. Maintain 95%+ Confidence - Only 5% false positive risk
  3. Avoid Peeking - Multiple checks inflate false positive risk
  4. Account for Novelty Effect - New designs perform better initially
  5. Identify Confounds - External events can skew results
🔴 Common Pitfalls:
  • Peeking at results (increases false positives from 5% to 20%+)
  • Stopping early when lift looks good (before sample size)
  • Not accounting for novelty effect (new designs initially outperform)
  • Testing without calculating sample size first
  • Confusing percentage points with relative lift

2.1 Visual Experience Composer (VEC)
VEC: Point-and-click visual interface for creating experiences without coding
What VEC Can Edit
  • ✓ Text content (headlines, copy, button labels)
  • ✓ Images (replacements, modifications)
  • ✓ Styling (colors, fonts, spacing)
  • ✓ Structure (hide/show, rearrange, remove, add)
  • ✓ Links & attributes (URLs, alt text, titles)
What VEC Cannot Edit
  • ✗ iFrames (browser security)
  • ✗ Heavily JavaScript-rendered content
  • ✗ Third-party widgets
  • ✗ Server-side dynamic content
CSS Selector Stability: This is a frequent exam topic. Avoid deeply nested selectors. Use Expand Section to select parent elements (especially those with unique IDs).
Key VEC Features
Feature Purpose When to Use
Expand Section Select parent element for stability When selectors break after page updates
!important CSS Override page CSS conflicts When Target CSS doesn't appear
URL Targeting Apply activity to multiple pages Multi-page campaigns
Edit HTML Direct code editing Complex changes, JavaScript issues
2.2 Form-Based Experience Composer
Form-Based Composer: Non-visual interface for creating experiences without page rendering
When to Use Form-Based
  • Non-website channels (email, apps, APIs, kiosks)
  • VEC fails to load pages
  • JavaScript-heavy pages with timing issues
  • Protected pages (authentication required)
⚠️ Critical: Redirect offers can ONLY be created in Form-Based Composer, NOT in VEC.
Content Types in Form-Based
  • HTML Offer: Custom HTML code
  • JSON Offer: Structured data for SPAs/APIs
  • Image Offer: Image URL replacement
  • Redirect Offer: Send to different URL (Form-Based only)

DOMAIN 3

Domain 3: Analyzing & Reporting (16%)

3.1 Understanding Statistical Concepts
Conversion Rate
Formula: (Conversions / Visitors) × 100
Example: 50 conversions / 1,000 visitors = 5%
Lift
Formula: (Variation% - Control%) / Control% × 100
Example: (6% - 5%) / 5% × 100 = 20% lift
⚠️ Common Confusion: 20% lift in relative terms ≠ 20 percentage points
20% relative lift = 1 percentage point absolute difference (5% → 6%)
Confidence and Significance
Confidence Level False Positive Risk Action
95%+ Confidence 5% (acceptable) DECLARE WINNER
80-94% Confidence 6-20% (high risk) Continue testing
<80% Confidence >20% (very high) Much more data needed
Sample Size Importance: You MUST reach calculated sample size before declaring winner, even if confidence seems high at 85-90%.
3.2 Automated Personalization Reporting
Report 1: Activity Level Report
  • Shows: Control (random) vs. Targeted (AI)
  • Answers: "Is personalization working?"
Report 2: Offer Level Report
  • Shows: Each offer's Random vs. Smart performance
  • Key: Compare same offer (Random vs. Smart), NOT different offers
Report 3: Automated Segments Report
  • Shows: Auto-discovered visitor groups
  • Reveals: Which segments prefer which offers
Report 4: Important Attributes Report
  • Shows: Which attributes ML used most
  • CRITICAL MISUNDERSTANDING: This is FREQUENCY of use, NOT causation
🔴 Important Attributes Mistake:
❌ "Device Type causes 28% of conversions"
✅ "Algorithm used Device Type in 28% of decisions"
3.3 Multivariate Testing Reporting
Experience Performance Report
  • Shows each element combination's performance
  • Comparison of all combinations side-by-side
Element Contribution Analysis
  • Breaks down impact of individual elements
  • Shows which variables matter most
Bonferroni Correction
  • What it does: Adjusts significance threshold for multiple comparisons
  • Why: Testing many elements inflates false positive risk
  • Solution: Stricter threshold per comparison
3.4 Interpreting Confidence Intervals
Example:
Variation: 6.2% ± 0.4%
95% Confidence Interval: 5.8% - 6.6%
Means: 95% confident true rate is between 5.8% - 6.6%
Overlapping vs. Non-Overlapping Intervals
  • Intervals OVERLAP: No significant difference (continue testing)
  • Intervals DON'T OVERLAP: Significant difference (safe to declare winner)
Domain 3 Summary
  • Understand conversion rate, lift, confidence calculations
  • Know 95%+ confidence requirement for declaring winner
  • Know sample size is CRITICAL (non-negotiable)
  • Understand false positive risks and causes
  • Know AP's 4 unique report types
  • Remember: Important Attributes ≠ causation
  • Understand novelty effect in test interpretation
  • Can interpret confidence intervals

Domain 4: Troubleshooting (8%)

4.1 Activity Delivery Troubleshooting
Systematic Troubleshooting Checklist
  1. Verify Activity Status: Active? Past start date? Before end date?
  2. Verify Audience: Do you match audience rules?
  3. Verify URL Targeting: Current page matches URL rules?
  4. Clear Browser Cache: Try incognito/private mode
  5. Check Target Library: at.js or alloy.js loaded in console?
  6. Check Collisions: Higher priority activities hiding yours?
  7. Verify CSS Selectors: Page design changed? Selectors broken?
4.2 Audience Qualification Issues
Common Audience Problems
  • No visitors qualify: Check AND/OR logic, attribute population
  • Wrong audience assigned: Verify audience definition
  • Profile attributes missing: Confirm parameter passing
Debug Checklist:
  • Check browser console for mbox calls
  • Verify parameters are being sent
  • Check parameter names match exactly
  • Validate audience works in isolation

Tool Purpose Detail Level When to Use
mboxDebug (?mboxDebug) Basic request/response inspection Low Quick checks

Preset: Saved reporting configuration that depends on referenced objects (audiences, metrics)
When Presets Become Invalid

  • Referenced metric removed
  • Referenced objects changed/renamed
Fixing Invalid Presets
  1. Identify missing/changed object
  2. Recreate with original definition (or update references)
  3. Preset automatically becomes valid

Understanding "Match Audience Rules to See Experiences"

Critical Exam Concept: QA Preview Modes

You've just identified an important exam question we need to cover deeply. Let me explain all QA/Preview settings in Adobe Target.

What is QA Mode?

QA (Quality Assurance) Mode in Adobe Target allows you to:

  • Preview activities before going live
  • See how experiences will appear
  • Test without affecting real data/reporting
  • Validate audience targeting
  • Check experience delivery

The 3 Main QA/Preview Options

Option 1: "Show Default Content for All Other Activities"

Setting: ON or OFF

What it does:

  • ON = Preview ONLY your activity in isolation (ignore all other live activities)
  • OFF = Preview your activity WITH other live activities included (realistic view)

Use case:

  • ON: "Does my activity's content work in isolation?"
  • OFF: "How does my activity look alongside other live activities?"

Example:

You have Activity A (button color) and Activity B (banner text) running on homepage

Preview with "Show default content" ON:
├─ See only: Banner with your test button color
├─ Other activities: Ignored
└─ View: Isolated, clean

Preview with "Show default content" OFF:
├─ See: Banner with your test button color + Activity B's banner text
├─ Other activities: Included (with collision/priority applied)
└─ View: Realistic production scenario
Option 2: "Match Audience Rules to See Experiences"

Setting: ON or OFF

What it does:

  • ON = Preview shows activity ONLY if you match all audience rules
  • OFF = Preview shows activity regardless of whether you qualify for audiences

Use case:

  • ON: "Will only qualified visitors see this experience?"
  • OFF: "Let me see the experience even if I don't match the audience"

Example:

Activity audience rules:
├─ Country = United States
├─ Device Type = Mobile
└─ Visitor Type = Returning

Preview with "Match audience rules" ON:
├─ If you're accessing from US on mobile as returning → See activity ✓
├─ If you're accessing from Canada → Don't see activity ✗
├─ If you're on desktop → Don't see activity ✗
└─ View: Only see if you fully qualify

Preview with "Match audience rules" OFF:
├─ You see activity regardless of:
│  ├─ Where you're accessing from
│  ├─ Device type
│  └─ Visitor status
└─ View: Always see the experience to test it

WHY THIS MATTERS:

  • Ensures audience rules are working correctly
  • Validates that the right visitors see the right experiences
  • Catches audience misconfiguration before launch
Option 3: Activity Assignment Method (Less common but worth knowing)

Some preview modes let you control:

  • Direct URL = Use special URL parameters to preview
  • QA Link = Generate a unique QA link to share
  • Bookmarklet = Use browser bookmarklet for quick preview toggle

How These Work Together

Scenario 1: Preview in Production Environment

You want to preview an activity that's already live on your site.

Best Settings:

  • Show default content: OFF (see realistic collision/priority)
  • Match audience rules: ON (only if you qualify)

Why:

  • OFF = see how it appears with other activities
  • ON = only if you match the audience (production behavior)
Scenario 2: Debug Audience Targeting

You think audience rules aren't working correctly.

Best Settings:

  • Show default content: ON (isolate your activity)
  • Match audience rules: OFF (force show even without qualifying)

Why:

  • ON = see only your activity (eliminate other factors)
  • OFF = bypass audience rules (test experience content regardless)
  • If you see the experience with OFF but not with ON = audience rule issue
Scenario 3: Content Quality Check

You just want to see if your offer/experience content looks good.

Best Settings:

  • Show default content: ON (minimize distraction)
  • Match audience rules: OFF (don't block you with audience rules)

Why:

  • ON = see only your content
  • OFF = bypass audience qualification
  • Focus on: Does the experience look right?
Scenario 4: Production Simulation

You want to see exactly what a qualified visitor will see in production.

Best Settings:

  • Show default content: OFF (include other activities)
  • Match audience rules: ON (only if you qualify)

Why:

  • OFF = realistic with other activities
  • ON = only if you match audiences
  • Result: Exactly what real visitor sees

How to Access QA Mode

In Visual Experience Composer (VEC):
Step 1: Open your activity
Step 2: Click "QA" button (top right)
Step 3: Configure preview settings
Step 4: See toggle options for:
├─ Show default content for all other activities
├─ Match audience rules to see experiences
└─ [Optional] Preview mode selection
Step 5: Click checkboxes to toggle ON/OFF
Using QA URL Parameters:

Adobe Target uses special URL parameters for QA preview:

Standard QA Preview:
https://yoursite.com/page?at_preview_token=TOKEN&at_preview_index=0_1

This bypasses normal activity delivery and shows preview mode

Available parameters:
├─ at_preview_token = unique token for your session
├─ at_preview_index = which experience to preview
├─ at_preview_mode = enter/exit QA mode
└─ at_debug = additional debugging

Important Considerations

Data Not Recorded in QA Preview

When you preview activities using QA mode:

  • ❌ Conversions are NOT counted
  • ❌ Visitor impressions are NOT tracked
  • ❌ Reporting is NOT affected
  • ✅ Only YOU see it (other visitors unaffected)

Why this matters for exam:

  • QA preview is safe to use on live activities
  • It doesn't pollute your test data
  • Perfect for testing production environment
Audience Rules Match - Common Scenarios

Scenario A: Geo-targeting audience

Activity audience: "Visitors from California"

Match audience rules ON:
├─ You're in California → See activity
└─ You're in Texas → Don't see activity

Match audience rules OFF:
├─ You're in California → See activity

Match audience rules OFF:
├─ First visit → See activity anyway (bypass rule)

Scenario C: Complex AND rules

Activity audience: 
├─ Country = USA
├─ Device = Mobile
└─ Visitor Type = Returning

Match audience rules ON:
└─ Must meet ALL 3 criteria to see activity

Match audience rules OFF:
└─ See activity regardless of above rules

Exam Question Patterns

Pattern 1: Identify the Setting

"A QA specialist wants to preview an activity ONLY if they actually qualify for the audience rules, mimicking what a real visitor would see. Which setting should they enable?"

Answer: "Match audience rules to see experiences" = ON

Pattern 2: Debug Scenario

"An activity targeting 'Mobile users in the US' isn't showing during preview. The practitioner wants to bypass audience rules to test if the experience content is correct. What should they do?"

Answer: Toggle "Match audience rules to see experiences" to OFF

Pattern 3: Isolation vs. Realistic

"A practitioner wants to preview an activity with all other live activities included to see realistic collision/priority behavior. Which settings are needed?"

Answer:

  • "Show default content for all other activities" = OFF
  • "Match audience rules to see experiences" = depends on if they qualify
Pattern 4: Production Simulation

"What preview settings best simulate what a real visitor will see in production?"

Answer:

  • "Show default content for all other activities" = OFF (include other activities)
  • "Match audience rules to see experiences" = ON (only if they qualify)

  • Your preview = invisible to real visitors

❌ WRONG: Not knowing when to use ON vs. OFF

  • OFF = Debugging/testing content (less common)

Practice Question

Question: A Target practitioner has an activity targeting "Returning mobile visitors from the US." They want to preview the activity in their current QA environment, but they're accessing from a desktop browser in Canada. Which settings allow them to still see the experience to verify the content is correct?

A) "Match audience rules" ON; "Show default content" ON
B) "Match audience rules" OFF; "Show default content" ON ← Best answer
C) "Match audience rules" OFF; "Show default content" OFF
D) "Match audience rules" ON; "Show default content" OFF

Explanation:

  • "Match audience rules" OFF = bypass audience qualification (you don't qualify but see it anyway)
  • "Show default content" ON = see only your activity in isolation
  • Result: See the activity content even though you're not a qualified visitor

Key Takeaway for Exam

"Match audience rules to see experiences" is a QA setting that controls whether you (the QA person) must actually qualify for an activity's audiences to see it in preview mode. ON = must qualify. OFF = see it regardless.

This is different from whether the activity actually targets certain audiences—the audience rules are always in place for real visitors. This setting just controls your preview experience.

3. Post-Conversion Behavior (Q5)

Official Documentation Reference:

When you set a success metric, you have 3 post-conversion options:

Option 1: "Keep User in Activity" (DEFAULT)
├─ Visitor stays in activity after conversion
├─ Can convert multiple times
├─ Use when: Want repeat conversions counted

Option 2: "Release & Allow Reentry"
├─ Visitor exits activity after conversion
├─ Can re-enter the activity in future sessions
├─ Use when: One conversion per session, but allow future participation

Option 3: "Release & Bar Reentry"
├─ Visitor removed from activity permanently after conversion
├─ Cannot see activity again
├─ Use when: One-time offer, don't want repeat conversions

Scenario: "Users should only convert once, then excluded from activity"

Answer: "Release & Bar Reentry" setting

Scenario: "Want to count multiple purchases by same visitor"

Answer: "Keep User in Activity" (default) OR "Release & Allow Reentry"

6. Auto-Target Attribution Rules (Q49)

Key Concept:

AUTO-TARGET CONVERSION COUNTING:

A visitor counts for conversions ONLY IF:
├─ They qualify for the activity AND
├─ They actually see/view the activity AND
├─ They convert in the same session

If visitor qualifies but DOESN'T see the activity:
└─ Their conversions are NOT counted in the activity report

Comparison:
├─ A/B Test: All activity participants get credit
└─ Auto-Target: Only participants who viewed activity get credit

  • https://experienceleague.adobe.com/docs/target/using/activities/auto-target/auto-target-to-optimize.html

For Your Exam:

Answer: "Only if visitor sees activity within same session"

Scenario: "Does conversion count if visitor never sees Auto-Target activity?"

Answer: "No, only visitors who qualified AND viewed count conversions"

8. Sample Size & False Positives (Q44)

Core Statistical Concept:

Reaching the calculated sample size ensures statistical power (80%) and significance (95% confidence), which minimizes the risk of false-positive results in the test.

Why Sample Size Matters:

Without Sample Size (Peeking):
├─ Day 3: Variation shows 8% lift
├─ Declare winner: 60% confident
├─ 40% risk of false positive
└─ Implement losing variation → Bad decision

With Sample Size (Proper Testing):
├─ Day 21: Reach 10,000 visitors
├─ Check confidence: 95%
├─ 5% risk of false positive
└─ Safely declare winner

FALSE POSITIVE = declaring winner when none exists

Study Resources:

  • https://experienceleague.adobe.com/docs/target/using/activities/ab-test/sample-size-determination.html

For Your Exam:

Question: "Why wait for sample size in A/B testing?"

Correct Answer: "Minimizes the risk of false-positive results"

Other terms for same concept:
- "Reduces Type I error"
- "Ensures statistical significance"
- "Avoids peeking bias"
